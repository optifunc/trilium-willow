Willow Mind Map for Trilium

Experimental add-on for stock Trilium Notes v0.105.0. Tested in Chrome and the macOS desktop app. Other Trilium versions and desktop operating systems have not been verified. The editor and styles are bundled here; no CDN or extra server is needed.

Install

  1. Import the release ZIP under a note of your choice using Trilium's native Import action. Keep archive extraction enabled. Import this whole subtree, including its shared editor, template, and example.
  2. With safe import enabled, Trilium disables executable relations. Open the Willow Mind Map template and click Enable render note, then do the same on Example mind map. This activates their renderNote relations. Alternatively, for a package whose code you trust, expand the import dialog's Options and uncheck Safe import.
  3. Open Example mind map to verify the editor. Reload Trilium if the template menu has not refreshed.

Create and edit maps

Create your documents outside this add-on subtree. Right-click a note in the tree, then Insert note after or Insert child note → Templates → Willow Mind Map. The native title and the initial root label “Mind map” are independent. F2 edits a node, Enter commits, Tab adds a child. Changes autosave; Trilium's note header shows saving state. Cmd/Ctrl+Shift+0 fits the map. The first opening centres the root at 100%.

Zoom, position and selection stay local to each browser/desktop profile. Click a map in the tree to focus it for arrow-key navigation. Split panes preserve independent views, with one editor at a time.

Update an existing installation

  1. Wait for all maps to show Saved and finish any conflict recovery. Back up the existing add-on subtree using native export.
  2. Open the existing Willow shared editor Code (JSX) note. Replace its entire code with the contents of the new release's willow-editor.jsx file. Keep the existing note ID, JSX type, and MIME type. Update its willowVersion label to the version in the release manifest.
  3. Wait for Trilium to save the code, then reload every open client. Open an existing map and create a new one to check the update. Keep the existing template and map relations. This update procedure applies to document-format-v1 compatible releases; a future format change requires separate migration instructions.

Importing another ZIP creates another installation with new IDs; it does not update existing maps. For rollback, restore the previous shared editor's code into the same note and reload. Do not delete the old editor as an upgrade procedure.

Remove and recover

Finish saving and recovery, move any maps you want to keep out of this subtree, then delete the add-on subtree. Reload open clients to unload the editor. User map notes retain their JSON; without a working editor relation, Trilium shows its native Render Note setup screen (“Display custom HTML or Preact JSX inside this note”). Note source still exposes the saved document. Native map-only export preserves the JSON but omits the external editor relation.

To resume editing after reinstalling, add an owned renderNote relation on each existing map pointing to the newly installed Willow shared editor, and add the label willowMindMap. This restores metadata lost when an old template was deleted. Do not replace the map's content. Restoring the deleted original subtree from Trilium's deleted notes can preserve its original IDs.

Limits

For a detected conflict, Keep both saves a recovery map before loading the incoming version. Use incoming asks before discarding your draft. Drafts remain in memory until saved; forced termination can lose unfinished work. A desktop close attempt commits an unfinished label and waits for saving; retry closing after Saved or resolve the reported error.

Trilium's native sync can choose one whole document when two devices already saved competing versions. Guaranteed preservation of both versions is outside this add-on's scope. Internal note links, migration from other map formats, and dedicated image/document export are deferred.
